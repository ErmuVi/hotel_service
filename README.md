# Сервис бронирования номеров отеля

Простой REST API сервис для управления каталогом номеров отеля и бронированиями. Проект разработан на **Python** с использованием фреймворка **Django** и СУБД **PostgreSQL**, полностью контейнеризирован с помощью **Docker** и покрыт автоматизированными тестами.

## 🛠 Стек технологий
* **Язык программирования:** Python 3.11
* **Фреймворк:** Django 6.1 (без использования DRF)
* **База данных:** PostgreSQL 15
* **Пакетный менеджер:** Poetry
* **Конфигурация:** Pydantic-settings (валидация переменных окружения из `.env`)
* **Линтеры/Форматтеры:** Ruff
* **Тестирование:** Pytest + Pytest-Django

## 🚀 Инструкция по запуску

Для запуска проекта вам понадобится установленный **Docker** и **Docker Compose**.

1. Клонируйте репозиторий и перейдите в папку проекта:
   ```bash
   git clone https://github.com/ErmuVi/hotel_service.git
   cd hotel_service
   ```

2. Запустите сборку и подъем контейнеров (сервис Django и база данных PostgreSQL поднимутся автоматически):
   ```bash
   docker compose up --build
   ```
   *После этого сервис будет доступен локально по адресу: `http://localhost:8000/`.*

## 🧪 Запуск автоматизированных тестов

Проект покрыт юнит-тестами с использованием `pytest`. Тесты проверяют успешное создание комнат и логику бронирования.

Для запуска тестов внутри изолированного Docker-контейнера выполните команду в новом окне терминала:
```bash
docker exec -it hotel_web_conteiner python -m pytest
```

Для проверки чистоты кода линтером `ruff` выполните:
```bash
docker exec -it hotel_web_conteiner poetry run ruff check .
```

## 💡 Принятые решения и особенности реализации

В соответствии с требованиями и для демонстрации навыков проектирования были приняты следующие архитектурные решения:

1. **Формат входных данных:** Согласно примерам из ТЗ, HTTP-хендлеры принимают данные в формате стандартной HTML-формы (`application/x-www-form-urlencoded`), а на выходе строго возвращают JSON. В случае ошибок возвращается JSON со статус-кодами линейки `4xx/5xx` и текстовым описанием проблемы.
2. **Бизнес-логика (Дополнительное усложнение):** Реализована строгая проверка пересечения дат при создании бронирования. Если номер уже занят на указанные даты (или частично пересекается), сервис вернет ошибку `400 Bad Request`. Используется эффективный алгоритм проверки интервалов на уровне базы данных средствами Django ORM (`__lt` и `__gt`).
3. **Каскадное удаление:** При удалении номера отеля (`/rooms/delete`) база данных автоматически удаляет все связанные с ним бронирования благодаря каскадной связи `ON DELETE CASCADE`.
4. **Структура проекта:** Использован современный стандарт **src-layout** (весь исходный код приложения изолирован внутри директории `src`).
5. **SQL-схема базы данных:** В корне проекта подготовлен файл `schema.sql` с ручными SQL-запросами для создания структуры таблиц в PostgreSQL, удовлетворяющий требованиям ТЗ.

## 📂 Примеры API запросов

### 1. Добавить номер отеля
* **Метод:** `POST`
* **URL:** `/rooms/create`
* **Параметры формы:** `room_description` (string), `price_room` (decimal)
```bash
curl -X POST -d "room_description=Люкс с видом на море" -d "price_room=7500.00" http://localhost:8000/rooms/create
```
* **Ответ (201 Created):** `{"room_id": 1}`

### 2. Получить список номеров отеля с сортировкой
* **Метод:** `GET`
* **URL:** `/rooms/list?sort_by=price_room&order=desc` (доступна сортировка по цене `price_room` или дате `created_at`, порядок `asc` / `desc`)
```bash
curl -X GET "http://localhost:8000/rooms/list?sort_by=price_room&order=desc"
```

### 3. Добавить бронь номера
* **Метод:** `POST`
* **URL:** `/bookings/create`
* **Параметры формы:** `room` (ID номера), `start_booking` (YYYY-MM-DD), `end_booking` (YYYY-MM-DD)
```bash
curl -X POST -d "room=1" -d "start_booking=2026-10-01" -d "end_booking=2026-10-05" http://localhost:8000/bookings/create
```
* **Ответ (201 Created):** `{"booking_id": 1}`
